# v1.1 — Task kinds, navigation, metadata, polish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.1 of the TA load-distribution app: independent light/heavy task fairness, a three-pill navigation, full metadata + icons, every deferred review minor fixed, and a visual/motion polish pass.

**Architecture:** The pure engine gains `TaskKind` and `ledgers: Record<TaskKind, Ledger>`; a pure `upgradeWorkspace` runs on every server read so stored documents never break. UI changes ride on the existing page/components structure; the nav becomes three independent pills in `Header`/`NavBar`; metadata is per-route `meta()` + `public/` assets generated by a headless-Chrome script. Minors and polish are grouped by area so each task has one review surface.

**Tech Stack:** unchanged (React Router 8.4 SSR, Vite 8, Tailwind v4, motion 14, dnd-kit, date-fns, supabase-js, Vitest 5). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-17-v1-1-task-kinds-nav-polish-design.md`

## Global Constraints

- Engine (`app/engine/`) stays pure and must not import from `app/lib` or `app/components`.
- Two independent ledgers: every ledger operation uses `ws.ledgers[task.kind]`; swaps only within a kind.
- `upgradeWorkspace` is idempotent and returns the same reference for current documents.
- Secrets only in `*.server.ts`; `APP_URL` is the only new env var.
- No AI-attribution trailers or tool mentions in commits or files (user requirement).
- ≥44px targets; every animation (incl. non-transform tweens) disabled under reduced motion; `useMounted` for markup-changing reduced-motion branches; hydration-safe; theme tokens only.
- All mutations through `useCommand`; preview never saves.
- `npm test`, `npm run typecheck`, `npm run build` green before every commit.

## Review Focus

1. A heavy task must never change a light gauge/turn and vice versa — including `removeTA`, `setSemester` extension and `redistributeAll` (Task 1 tests).
2. A legacy document (single `ledger`, tasks without `kind`) must load, render and accept commands without a 500 (Task 2 `legacy document upgrades on load and is written back once`).
3. A swap across kinds must be impossible from every UI path and rejected by the engine (Task 1 + Task 3 tests).
4. The new per-call fetcher keys must still revalidate the root loader and show exactly one toast per command (Task 6 tests).
5. Page `<title>`/OG tags must be correct on SSR (Task 5 route tests).
